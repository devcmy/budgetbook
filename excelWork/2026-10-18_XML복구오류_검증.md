# Excel 복구 로그: 잔액 탭 sheet4.xml 로드 오류

작업일 2026-10-18. 사용자가 보낸 Excel 복구 로그는 `/xl/worksheets/sheet4.xml`의 XML 로드 오류를 보고했습니다. 저장소의 오류 발생 기준본 `0ca6922`를 [history/2026-10-18/02](history/2026-10-18/02/README.md)에 보관하고, 원본 셀을 보존한 상태에서 해당 파트의 요소 순서만 정정했습니다. SharePoint 파일에 직접 접속하거나 Excel 자동 복구본을 바탕으로 재구성하는 작업은 아닙니다.

## 확인된 원인

`sheet4.xml`은 잔액 탭입니다. 전체 입력 원장을 접는 설정을 추가하면서 `sheetPr`에 `outlinePr`를 맨 뒤에 붙였습니다. OOXML의 CT_SheetPr는 자식 요소 순서를 요구합니다.

- 오류 발생본: `tabColor → pageSetUpPr → outlinePr`
- 정상 순서: `tabColor → outlinePr → pageSetUpPr`

XML 문법 자체는 올바르기 때문에 XML 파싱·openpyxl 읽기·LibreOffice 재계산은 통과했지만, 이 순서는 스키마에 맞지 않습니다. 이전 월별 수식·캐시 검증만으로 Excel 로드 호환성을 보증하지 못한 검증 누락입니다. 복구 로그가 가리킨 파트에 실제 순서 위반이 존재함을 원본 비교와 독립 점검에서 확인했습니다.

## 수정 범위

`outlinePr`를 `pageSetUpPr` 앞에 옮기는 것만 변경합니다. 하단 월별 조회 기능을 제거하거나 원장을 다시 작성하지 않습니다.

- 원장 A64:Y500의 184건, 선택월 조회표·페이지·접기 설정·조회월 드롭다운은 유지합니다.
- 잔액·예비비·월간·RAW·매크로·버튼·그림·스타일을 유지합니다.
- 셀·수식·캐시는 다시 저장하거나 재계산하지 않습니다. `sheetData`를 바이트로 비교합니다.
- 압축을 푼 내용 기준으로 바뀐 ZIP 파트는 `xl/worksheets/sheet4.xml` 하나뿐이며 다른 모든 파트는 바이트가 같습니다.
- 생성 스크립트 `balance_selected_ledger.py`도 올바른 위치에 `outlinePr`를 삽입하도록 고치고, 생성 직후와 최종 파일 검사에 구조 검증을 추가합니다.

## 재발 방지 검증

`scripts/validate_excel_structure.py`와 `scripts/schemas/worksheet-properties.xsd`는 worksheet properties의 제한된 XSD 및 주요 구조 불변조건을 검사합니다. **전체 ECMA-376 스키마 검증 도구는 아닙니다.** CT_SheetPr 순서·지원 속성과 전체 워크시트의 주요 요소 순서, 행·셀 정렬/중복, 열 범위, 일부 목록 count 등을 확인합니다.

`scripts/repair_balance_xml.py`는 오류본에서 검사가 실패함을 확인한 후 한 파트를 수정하고, 수정본의 구조 검사와 셀·수식·캐시 및 다른 파트의 바이트 보존을 검증합니다. 결과·현재 해시는 [excel_xml_repair_validation.json](excel_xml_repair_validation.json)에 기록합니다. 실제 Excel 데스크톱의 파일 열기는 이 환경에서 실행하지 못했으며, SharePoint의 기존 파일은 수정본으로 교체한 뒤 다시 열어 확인해야 합니다.

## 검증 결과

- 오류본의 `sheet4.xml`에서 요소 순서 위반 1건을 재현했습니다.
- 수정본은 워크시트 46개와 XML 파트 82개의 제한된 구조 검사에서 오류가 없습니다.
- 정상·오류 구조를 포함하는 단위 테스트 14개를 통과했습니다.
- 수정된 생성 스크립트로 이전 정상본에서 조회 기능을 다시 생성하는 회귀 검사도 통과했습니다.
- 모든 셀·수식·계산 캐시와 나머지 ZIP 파트는 수정 직전 보관본과 바이트가 같습니다. 재무 금액이나 조회 기능 변경은 없습니다.
