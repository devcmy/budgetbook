# 예비비: 현황 / 계획 / 이체 내역

현재 화면은 [10/19 예비비 현황·결제대금 연동](2026-10-19_예비비현황_결제대금연동_검증.md)으로 후속 개편했습니다. 정산대기 현황 열은 제거했고 사용계획을 별도로 추가했으며, 검증 탭도 삭제했습니다. 아래는 최초 개편 당시 설명·검증 이력입니다.

후속 정정: 현황 헤더를 ‘선택월 예비비 사용액’으로 바꾸고 생신 본인 사용을 200,000원에서 239,000원으로 정정했습니다. 명절비 200,000 + 임시보관 39,000원이며, 원금 61,000원 회수를 반영했습니다. 아래 개편 당시 금액·8건 연결·이전 검증 해시는 이력입니다. 현재는 9건 연결이며 [생신 정산·명칭 수정](2026-10-15_생신정산_검증.md)과 `family_event_validation.json`이 최신입니다.

기준일: 2026-10-15. 최신 파일은 [테트리스_가계부_2026_고도화.xlsm](테트리스_가계부_2026_고도화.xlsm)입니다. 변경 전 버전은 [history/2026-10-15/03](history/2026-10-15/03/README.md)에 보관합니다.

## 화면과 사용법

예비비 한 탭에 세 영역을 배치했습니다. 별도 정산 탭은 만들지 않습니다. 잔액 탭의 화면·원장 입력·조회월 드롭다운·잔액 값은 유지합니다.

1. **현황(6~16행)**: 목적별 원장잔액 / 정산대기 / 사용가능액 / 선택월 사용액. `원장잔액 − 정산대기 = 사용가능액`입니다. 기본 조회월은 10월이며 `B3`에서 1~12월을 고릅니다.
2. **계획(18~30행)**: 행사·목적별 한 줄에 2026년 1~12월 적립계획을 배치했습니다. 노란색 금액을 수정하면 해당 월의 월간 계획표와 잔액 탭의 계획 열에 연결됩니다. 계획을 입력했다고 실제 잔액이 늘지는 않습니다.
3. **이체 내역(32~69행)**: 선택월 사용, 해당 월에 정산한 이전 사용, 이전 달부터 남은 미정산을 함께 조회합니다. 사용별 사용액·당월 정산·누적 정산·미정산과 원장 변동을 같은 화면에서 확인합니다. 12건씩 페이지로 조회하며 전체 건수를 표시합니다. 조회월 변경 후 입력 페이지가 범위를 벗어나면 유효 페이지로 자동 보정합니다.

예비비와 잔액의 조회월은 독립적입니다. 예비비 원장잔액은 **선택한 월의 동일한 WRAP 원장**으로 계산합니다. 두 화면의 조회월이 같으면 계정별 금액을 직접 대조해 ‘일치’를 표시하고, 다르면 상단에 잔액 탭의 조회월을 안내합니다. 다른 월의 숫자를 같다고 표시하지 않습니다.

1~2월은 사용·계획 기록은 보여주되 WRAP 원장 자료가 없어 잔액·사용가능액·미정산은 ‘원장 없음’으로 표시합니다. 원장이 없는 기간의 실제 송금일이나 미정산 상태를 추정하지 않습니다. 미래 월은 현재 기록의 이월액이며 예상 수입·예정 지출을 자동 반영한 예측치가 아닙니다.

## 사용과 정산의 처리

- 카드 사용 시: 해당 예비비에서 부담한다고 **지정한 금액만** 정산대기에 잡고 사용가능액을 줄입니다. RAW 분류가 여행·선물이라는 이유만으로 예비비를 차감하지 않습니다.
- 다음 달 이체 시: 이미 기록한 사용ID에 실제 원장행을 연결합니다. 원장잔액과 정산대기가 같은 금액만큼 줄어들어 사용가능액은 이체로 다시 차감되지 않습니다.
- 선이체 시: 현금은 이체월에 원장에서 빠지고, 사용은 실제 사용월에 집계합니다. 이미 보낸 금액은 사용월에 다시 차감하지 않습니다.
- 다른 계좌에서 카드대금이 먼저 출금돼도 그 자체로 예비비 정산 완료가 되지 않습니다. 예비비 자금 이동과 연결해야 합니다. 같은 금액의 거래라는 이유만으로 자동 연결하지 않습니다.
- 한 사용을 여러 번 나누어 정산하거나, 한 이체를 여러 사용에 배분할 수 있습니다. 사용액 또는 원장 출금액을 초과하는 연결, 중복 RAW 사용, 잘못된 출금 계정은 확인 표시를 띄우고 정상 정산으로 인정하지 않습니다.
- 사용가능액이 음수면 그대로 표시하고 부족 안내를 띄웁니다. 금액을 0원으로 덮거나 임의로 생활비에서 보충하지 않습니다.

## 고정 등록 자료와 자동 조회표

월을 바꾸는 자동 조회표에 직접 금액·분류를 입력하면 다음 월의 다른 거래에 그 입력이 붙는 문제가 생깁니다. 이를 막기 위해 **입력은 고정된 사용ID / 원장행에 저장**하고, 위 화면은 자동으로 조회합니다.

- **사용 등록**: 98행 아래, 왼쪽 `+`로 펼칩니다. 100~399행 300건이며 처음 78건은 기존 사용·비고정 거래 후보입니다. `C열=생활비`인 후보는 예비비 잔액에서 차감하지 않습니다. 필요한 거래의 C열을 예비비 항목으로 바꾸면 됩니다. 새 RAW 거래는 빈 행의 F열에 RAW행을 입력하고 C열을 지정합니다. 일자·내용·금액은 RAW에서 가져옵니다. 일부만 예비비로 부담한다면 E열을 본인 부담 범위 안에서 수정합니다.
- **이체 연결**: 428행 아래, 왼쪽 `+`로 펼칩니다. 430~729행 300건이며 기존 연결 8건을 보존했습니다. B열 사용ID, C열 원장행을 지정하면 날짜·출금계정·계좌·금액을 가져옵니다. 일부 연결은 D열 금액을 수정합니다.
- 입력 자료와 보조 계산은 기본적으로 접어 둡니다. 위 화면의 ‘등록 N행 확인’ 링크는 등록 영역으로 이동하며, 해당 행을 보려면 `+`를 펼칩니다.
- 기존 등록 자료의 ID·RAW행을 정렬하거나 바꾸지 말고 새 거래는 빈 행에 추가합니다. RAW 행번호와 원장행은 기존 통합문서의 연결 키이므로 원본 행 삽입·재정렬은 별도 연결 검증이 필요합니다. 등록 범위를 다 쓰면 수식·검증·입력 범위를 함께 확장해야 합니다.

현재 지원 단위는 **한 RAW 사용 건당 한 예비비 항목 + 나머지 생활비**입니다. 같은 RAW 거래를 여러 예비비에 중복 등록하면 확인 대상으로 처리합니다. 취소·환불·청구할인·복수 예비비 분담을 자동 추정해 정산하는 기능은 이번 범위에 넣지 않았습니다. 실제 원장 환입·원거래 연결 근거 없이 사용가능액을 늘리지 않습니다.

## 사용자 확인과 기존 기록의 연결

- 10월 숙박 39,000원·35,000원과 본인 철도 53,900원×2건, **합계 181,800원은 비고정 지출로 유지**합니다. 원래 명절비 용도였으나 해당 잔액을 이미 이동했으므로 현재 예비비에서 차감하지 않는다는 사용자 확인을 반영했습니다.
- 명절비 원장 계정명과 금액은 그대로 두고 계획 용도를 ‘본가 방문·명절’로 표시했습니다. 향후 숙박·교통까지 준비하는 용도이며 새 적립액을 임의로 입력하지 않았습니다.
- 가족행사 본인 부담 200,000원은 10월 사용과 9월 원장 223행의 명절비→가족통장 선이체를 연결했습니다. 기존에 확인된 이 교차계정 연결만 보존하며, 새 교차계정 정산을 임의로 허용하지 않습니다. 공동 행사 전체 실비 639,000원이나 식사 카드 139,000원을 본인 예비비 사용에 중복 가산하지 않습니다.
- 명절비 5월 51,100원, 상환비 5월 36,020원은 생활비로 이동한 금액이므로 **실제 사용액에서 제외**했습니다. 원장 이동 자체는 보존합니다. 해당 월 사용액은 각각 148,900원과 313,980원입니다.
- 휴가비 지원 200,000원의 사용일은 RAW 356행의 **2월 19일**을 따릅니다. 예전 예산의 ‘1월 예정/사용’ 칸을 실제 결제일로 오인하지 않습니다. 2월 명절 사용 100,000원은 기존 예비비 기록을 월간 사용표에도 연결했습니다. 이 과정은 목적별 사용 표시를 정리한 것이며 기존 월급 부담·총수입·총지출 값을 바꾸지 않습니다.
- 3월 기초 이전 사용 3건은 실제 송금일을 알 수 없어 ‘기초반영’ 근거로 보존했습니다. 3월 1일은 원장 시작 경계일이지 실제 송금일이라는 뜻이 아닙니다.
- 경조사비 원본 적립 기록 차이 100,000원은 `_예비비계산`과 검증 자료에 보존했습니다. 세부 생일·축의금에 임의 배분하거나 원장 잔액에 가산하지 않았습니다.

## 월간·계산기 연결

- 1~12월의 예비비 계획 `M48:M52`는 새 계획 입력으로 연결합니다.
- 목적별 실제 사용 `N64:N68`은 사용등록의 실제 사용월 기준으로 연결합니다. 이체월에 같은 금액을 새 사용으로 집계하지 않습니다.
- 본인 비고정 카드 사용을 예비비 부담으로 명시적으로 바꾸면 그 금액을 월간 월급 부담에서 제외합니다. 천원 올림 부담도 원거래 올림액과 잔여 생활비 올림액의 차이로 배분하며, 기존 계산기 색상 배치는 바꾸지 않습니다.
- 기존 9월 생일 50,000원처럼 이미 월급 부담에서 뺀 사용은 다시 차감하지 않습니다.
- 기존 달력과 색상 기록은 보존합니다. RAW 신규 거래를 추가했다고 모든 달력 날짜·테트리스 블록이 자동 생성되는 구조로 바꾼 것은 아닙니다. 새 RAW 반영 작업에서는 기존 절차대로 달력·색상·기준일도 함께 갱신해야 합니다.

## 보존과 검증

화면에서 제거한 기존 예비비 계산·차이표는 새 숨김 시트 `_예비비계산`에 보존했습니다. 표시 시트 29개와 순서는 유지하며, 총 시트는 기존 45개에서 46개(숨김 17개)입니다. 잔액·월간 계획 수식의 참조만 보존 자료로 연결하고 잔액 탭의 UI·입력·금액은 유지합니다.

도구:

- [redesign_reserve.py](scripts/redesign_reserve.py): XLSM 원본 패키지를 보존하면서 화면·등록·연결 수식을 작성
- [verify_reserve_redesign.py](scripts/verify_reserve_redesign.py): 월별·카드 사용/정산 순서·부분/일괄/중복 연결·기간 경계·페이지·계획 입력 시험
- [reserve_redesign_validation.json](reserve_redesign_validation.json): 최종 자동 검증 결과와 파일 해시

검증 결과: **1~12월 조회와 정산 시나리오 15개 통과**, 수식 오류 0건입니다. 시나리오에는 다음 달 정산·부분 정산·선이체·카드 선납 후 예비비 이동·일괄 이체·중복 사용/이체 거부·월말 시각·계획 입력·페이지 보정·잔액 부족·미래 이체의 과거 월 표시 차단을 포함합니다. 마지막 표시 조건 변경은 재무 수식·입력·다른 패키지 파트가 동일함을 바이트 대조한 뒤 기본 화면과 해당 기간 경계 사례를 다시 재계산했습니다.

VBA 프로젝트·버튼·그림의 바이너리와 기존 잔액/RAW 값, 예비비 외 기존 셀 스타일을 대조합니다. 이전 계산체인만 제거해 Excel이 새 의존관계를 다시 만들게 합니다. 수식 재계산은 VBA를 제거한 임시 XLSX에서 수행한 뒤 캐시만 XLSM에 옮깁니다. Excel 데스크톱의 매크로 실행·실제 드롭다운 클릭은 검증하지 않았습니다. 화면은 별도 임시 파일의 PDF로 배치를 확인합니다.
