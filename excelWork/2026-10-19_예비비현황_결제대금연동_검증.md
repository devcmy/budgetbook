# 예비비 현황·결제대금비 연동 및 검증 탭 삭제

작업 완료일 2026-10-19. 거래 자료는 기존 **10/18까지**이며 새 은행 거래를 추가하지 않습니다. 10/18에 시작하다 중단된 요청을 재개했습니다. 수정 전 기준본과 문서는 [history/2026-10-18/05](history/2026-10-18/05/SNAPSHOT.md)에 보관했습니다.

## 바뀐 현황 화면

예비비 현황은 **목적 / 선택월 사용계획 / 선택월 실제 사용액 / 사용가능액**으로 정리했습니다. 사용가능액은 맨 오른쪽이며, 정산대기·연결 확인 열은 현황에서 제거했습니다.

- `C8:C12`: 새 사용계획표에서 선택월 금액을 표시합니다.
- `F8:F12`: 선택월 실제 사용을 기존 고정 등록 자료에서 집계합니다.
- `I8:O12`: 잔액 탭의 같은 월·같은 목적 계정과 일치하는 사용가능액입니다.
- `13행`: 각 항목의 합계입니다. 두 탭의 조회월이 다르면 상단에 안내합니다.

사용계획은 지출이나 현금 이동이 아닙니다. 350,000원을 계획해도 210,000원을 실제로 썼다면 실제 사용분만 반영합니다. 계획 미입력은 `미입력`, 사용계획 없음으로 0원을 입력하면 `0원`으로 구분합니다. 계획 금액을 과거 실제 사용액이나 임의의 예시 금액으로 채우지 않았습니다.

## 적립계획과 사용계획을 분리

기존 `19~29행` 표는 매달 모을 **적립계획**이었습니다. 이것을 사용계획이라고 이름만 바꾸지 않았습니다.

| 영역 | 위치 | 입력·조회 기준 |
|---|---|---|
| 기존 적립계획 | 19~29행 | 기존 금액·목적·월간 계획 연결 보존 |
| 새 사용계획 | 32~40행 | 목적별 1~12월 예상 사용액, 입력칸 `D34:O38` |
| 사용·이체 내역 | 42~79행 | 기존 조회표를 10행 아래로 이동, 사용·정산 근거 확인 |
| 고정 사용 등록 | 100~399행 | 기존 ID·RAW행·분류·금액 유지 |
| 고정 이체 연결 | 430~729행 | 기존 사용ID·원장행 연결 유지 |

새 사용계획 금액은 모두 비워 두었습니다. 확정한 예산을 노란 칸에 입력하면 현황에 표시됩니다. 실제 적립이나 생활비·월급 배분이 바뀌지는 않습니다.

## 실제 사용과 WRAP 잔액을 맞추는 방식

사용을 등록했지만 아직 해당 돈을 이체하지 않았다면, 사용한 목적 계정에서 **결제대금비로 자동 확보**합니다. 이것은 WRAP 안의 계정 배분이지 새 은행 송금이나 새 소비가 아닙니다.

경조사비 450,000원 보유 상태에서 210,000원을 카드로 사용한 예시:

| 시점 | 경조사비 사용가능액 | 결제대금비 | WRAP 현금 합계* |
|---|---:|---:|---:|
| 사용 전 | 450,000 | 0 | 450,000 |
| 실제 사용 등록 | 240,000 | 210,000 | 450,000 |
| 나중에 결제대금비에서 실제 출금 | 240,000 | 0 | 240,000 |

\*다른 계정은 제외한 설명용 예시이며 운영 파일에 추가한 거래가 아닙니다.

사용가능액은 잔액 탭의 해당 목적 계정과 일치하고, 목적 계정·결제대금비·생활비 등 **모든 계정의 합계는 실제 WRAP 현금과 일치**합니다. 사용액을 실제 이체 때 다시 소비로 차감하지 않습니다.

기존처럼 목적 계정에서 직접 정산해도 중복되지 않습니다. 여러 번 나눈 정산, 다음 달 정산, 선이체도 구분합니다. 이체 내역의 `아직 옮길 돈`과 `확보된 결제대금비` 안내는 실제 자금 이동을 확인하는 정보이며 현황의 사용액에서 다시 빼는 별도 지출이 아닙니다.

실제 이체는 **사용ID·원장행으로 연결해야 합니다.** 결제대금비에서 지급했다면 그 출금 원장행을 연결합니다. 목적 계정→결제대금비의 수동 내부 이동을 이미 정산으로 연결한 경우에는 같은 사용액에 나중 카드대금 출금을 중복 연결하지 않습니다. 사용액·원장 금액을 넘는 연결과 잘못된 재원 연결은 경고로 처리합니다.

## 기존 생신·카카오페이 기록

생신 사용 **239,000원**은 이전에 확인한 명절비 **200,000원**과 임시보관 **39,000원**으로 이미 충당했습니다. 경조사비 450,000원에서 다시 차감하지 않습니다. 현황 아래에 재원을 명시했습니다. 경조사비 사용가능액 **450,000원**, 목적자금 합계 **2,150,000원**, WRAP 총액 **6,669,766원**은 기존과 같습니다.

가족통장 원금 61,000원 회수·생활비 이동과 카카오페이 충전/플라잉 더치 구매 연결 `KP20261017-01`도 보존합니다. RAW **2,485건**, 10월 **164건**, 본인 생활비 **1,476,900원**, 테트리스 **1,501,000원**은 변경하지 않았습니다.

## 원장과 월말표

실제 입력 원장 `잔액!A64:Y500`의 셀·수식·RAW 연결은 그대로입니다. 자동 확보 계산은 숨김 `_예비비계산`의 월별 자료에 별도로 저장합니다. 은행 이체를 꾸며서 원장에 추가하지 않습니다.

잔액 탭 상단의 전월말·이체 및 분류 보냄/받음·계정별 잔액과 월말표에 같은 자동 확보를 반영합니다. 모든 행은 `전월말 + 입금 − 사용 − 보냄 + 받음 = 잔액`을 유지하고, 자동 분류 전후 WRAP 총액은 같습니다.

월말표의 날짜 조건도 **다음 달 1일 미만**으로 통일했습니다. 월말 당일 23:59처럼 시간이 있는 거래가 누락되지 않습니다. 미래 월 월말표는 기존처럼 미입력 공란이며, 상단에서 미래 월을 선택하면 현재 기록 기준 잔액을 이월해 보여 줍니다.

## 검증 탭 삭제와 검증 기록

사용자 요청에 따라 **검증 탭을 실제 삭제**했습니다. 숨김 탭으로 남겨 두지 않았습니다. 다른 시트에서 검증 탭을 참조하는 계산 수식이 없음을 확인한 후 해당 워크시트 파트·전용 이름 범위·관계를 제거하고 문서 속성·탭 인덱스·사용안내를 정리했습니다. 나머지 시트 ID와 VBA·버튼·그림은 유지합니다. 결과는 표시 **28개**, 숨김 **17개**, 총 **45개** 시트입니다.

검증은 엑셀 탭 대신 [외부 검증 보고서](reserve_cash_alignment_validation.json)와 [audit.json](audit.json)에 기록합니다. 월별 조회 **12개**, 카드 사용·부분/전액 정산·기존 목적계정 지급·선이체·다음 달 지급·계획 입력·중복/잘못된 연결·월말 시각·잔액 부족 등 **22개 시나리오**를 폐기용 사본에서 재계산해 통과했습니다. XML 구조·시트 삭제·수식 참조 이동의 단위 테스트 **30개**도 통과했습니다.

[패키지 추가 점검](reserve_package_integrity_validation.json)에서 원본 스타일 전체의 바이트 보존, 내부 관계 대상 존재, 인쇄영역의 시트 인덱스와 문서 시트 목록 일치를 확인했습니다. [변경 명세](reserve_cash_alignment_manifest.json)에 삭제된 검증 시트 파트와 새 화면 주소를 기록했습니다. 값만 옮긴 폐기용 PDF 미리보기로 현황·계획·이체 내역의 배치도 점검했습니다.

운영 XLSM을 openpyxl/LibreOffice로 다시 저장하지 않습니다. 매크로 없는 임시 사본의 계산 캐시만 원본 XLSM 패키지에 가져옵니다. 실제 Excel 데스크톱 파일 열기·VBA 실행 및 전체 ECMA-376 스키마 검증은 이 환경에서 수행하지 못했습니다. SharePoint의 파일은 직접 수정하지 않았습니다.

이전 날짜별 보고서와 해시는 당시 이력입니다. 현재 파일 해시·구조·검증 결과는 이번 보고서와 `audit.json` 최상위를 따릅니다.
