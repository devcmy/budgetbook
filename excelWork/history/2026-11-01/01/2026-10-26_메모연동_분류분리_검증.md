# 메모 단일화·분류 독립·운영 탭 연동

2026-10-26. 실제 거래 기준일은 2026-10-19입니다. 현재 기준본은 같은 폴더의 `테트리스_가계부_2026_고도화.xlsm`입니다.

## 바뀐 사용 방법

**메모는 RAW의 I열 한 곳에서 입력·수정·삭제합니다.** 이전 I열 ‘추가입력’과 M열 ‘비고’의 내용을 줄바꿈으로 합쳐 I열 ‘메모’로 모았습니다. 같은 문장이 두 칸에 있으면 한 번만 유지합니다. 기존 메모 내용은 잃지 않았으며, 변경 전 전체 파일은 `history/2026-10-26/02`에 있습니다.

| RAW 입력 칸 | 의미 |
|---|---|
| I 메모 | 자유롭게 쓰는 메모. 수정·삭제해도 금액·분류·본인부담·중복 여부는 바뀌지 않음 |
| J 재분류 | 대납·변동비·고정비 등 회계 분류 |
| K 본인부담 | 실제 본인 부담액 보정 |
| L 결제구분 | 본인·공동·정산대기 등 구분 |
| M 동일거래 구분 | 나머지 원본 거래 필드가 완전히 같은 실제 별개 거래를 구별할 때만 입력 |

예전 M열은 이제 메모 칸이 아닙니다. 기존 비고는 I로 옮겼으므로 내용을 삭제해서 없앤 것이 아닙니다. 새 거래는 이전처럼 A 일시, C~I 원본 거래를 빈 행에 붙여넣습니다.

대납이라고 메모에 적는 것만으로 본인 소비에서 제외하지 않습니다. **대납은 J 재분류에서 선택**합니다. 기존에 확정한 대납·부담액은 그대로 유지했습니다.

## 어떤 메모가 연동되나

- 1~12월의 `V4:V24`, `V26`: 해당 고정비 RAW 거래의 현재 메모를 표시합니다. “10/19 RAW 확인” 등 예전 고정 분석 문구를 메모인 것처럼 남겨두지 않습니다.
- RAW와 연결된 월별 추가 실지출 표의 I열: 해당 거래들의 현재 메모를 표시합니다.
- 1~12월 `V34:AA40`: 선택월 RAW 거래 메모를 5건씩 봅니다. W40에 페이지 번호를 입력합니다. 페이지가 범위를 벗어나면 유효한 페이지로 제한하여 조회합니다.
- 각 월 계산기 `A157:U162`: 월별 탭과 같은 페이지의 메모를 표시합니다. 메모의 존재·내용은 테트리스 금액이나 색상 계산에 쓰지 않습니다.
- 잔액 원장 `G64:G500`: 기존 W/X의 RAW 행 연결이 있는 기록은 해당 RAW 메모를 표시합니다.
- 예비비 사용등록 H열: F에 지정한 RAW 행의 메모를 표시합니다. 정산등록 I열은 연결된 잔액 원장 메모를 표시합니다.

**RAW I의 메모를 지우면 해당 거래의 연결된 메모도 빈칸이 됩니다.** 월별 메모 목록에서는 해당 항목이 빠지고 다음 메모가 당겨져 표시됩니다. 메모를 바꾸면 각 보기도 바뀝니다. 수정은 RAW에서 하며, 다른 탭의 표시 수식을 덮어쓰지 않습니다. Excel 계산 옵션은 자동으로 사용합니다.

RAW에 대응하는 거래가 없는 **별도의 수기 이월·과거 정산 기록의 독립 메모**와 숨김 과거 보관본은 이력으로 유지합니다. 이들은 RAW 메모의 복사본이 아니므로 RAW 메모 삭제로 지우지 않습니다. 안내·입력 방법 같은 일반 설명문도 삭제 대상이 아닙니다.

## 메모를 분류·중복 판단에서 분리

이전 자동화에는 두 경로가 있었습니다.

1. 새 거래 메모에 ‘대납/대리결제’가 있으면 대납으로 자동 분류.
2. 중복 거래의 키에 메모를 포함하여, 메모 수정만으로 중복 여부가 바뀔 가능성.

두 경로를 제거했습니다. 새 대납은 J에서 명시합니다. 중복은 **일시·자산·분류·소분류·내용·금액·유형·M 동일거래 구분**을 비교하며 I 메모를 비교하지 않습니다. 완전히 같은 원본 거래를 다시 붙여넣고 메모만 바꿔도 소비가 추가되지 않습니다. 실제로 별개 결제라면 M에 서로 다른 구분값을 넣습니다. 기존에 메모만 다른 별개 기록이 있는 경우 별도 구분값을 이관하도록 구현했지만, 이번 기준본에는 해당 충돌 그룹이 없었습니다.

숨김 AN ‘연동메모’와 AO ‘메모순번’은 표시 전용입니다. 메모가 빈칸인지를 확인해 화면 목록을 만드는 데만 사용하며, 소비·수입·예비비 재원 등의 분류 조건은 아닙니다. 기존 RAW/원장 행번호와 금액·재분류·본인부담은 유지합니다.

## 앞서 설명한 3번과 남은 범위

3번은 **메모 문제가 아니라 행에 남아 있는 수동 보정 문제**입니다. 예를 들어 기존 통신비 행의 A/C:I를 지우고 새 식비 4,200원을 붙여넣어도, J에 남은 ‘고정비’가 자동으로 지워지지 않아 식비가 고정비로 집계될 수 있다는 뜻입니다.

이번 요청은 메모의 분리·연동이므로, 거래 ID 기반 보정이나 전체 RAW 초기화까지 재설계하지 않았습니다. **다른 거래로 기존 행을 재사용하지 말고 새 빈 행에 추가**합니다. 전체 RAW 삭제 후 재입력은 안전한 초기화 흐름이 아닙니다. 과거 수기 기준값을 보존한 증감 방식이므로 잔여·음수가 생길 수 있습니다. 메모만 삭제하는 것은 이번에 안전하게 분리·검증했습니다. 향후 전체 교체 기능은 명시적인 수기 이력 분리·거래 ID 보정·추가 회귀 검사가 필요합니다.

WRAP 잔액·예비비 목적 계정 배분을 RAW에서 자동 등록하지 않는 기존 범위도 유지합니다. 잔액·예비비의 메모 표시만 변경하고 수식상 계정 배분·실제 금융값은 바꾸지 않았습니다.

## 검증·보존

단위·기존 회귀 검사는 **117개 통과**했습니다. 메모 삭제·수정 시험에서 **157,601개 기존 숫자·날짜/계산값을 비교해 차이 0**, RAW 연결 메모 **958개 칸의 비움**을 확인했습니다. 날짜·표시 전용 메모 순번/건수는 금융값과 구분했습니다.

- 변경 전 모든 금융 숫자·날짜·기존 월별 합계·계산기 분류별 칸수를 대조합니다.
- I 메모 전체 삭제 후 현재 RAW 연동 메모 보기들이 비워지고 금융 숫자가 유지되는지 재계산합니다.
- 메모 수정이 월별 고정비·추가 실지출·월별 목록·계산기·잔액·예비비에 반영되는지 재계산합니다.
- 메모에 ‘대납/대리결제’를 써도 분류가 바뀌지 않는지, J에서 대납을 선택하면 본인 부담 0을 유지하는지 검사합니다.
- 메모만 다른 동일 거래는 중복 제외, M 구분이 다른 실제 별개 거래는 각각 반영되는지 검사합니다.
- 12개월 메모 목록, 페이지 변경과 물음표·별표 등의 단순 메모 표시를 검사합니다.

- ZIP/XML 구조, VBA·그림·컨트롤 보존, RAW 보호·월 필터를 검사합니다. 검증 탭은 추가하지 않았습니다.
