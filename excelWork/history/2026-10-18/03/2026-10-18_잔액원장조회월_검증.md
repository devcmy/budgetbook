# 잔액 표의 월 기준 확인 · 선택월 원장 기본 조회

후속 XML 복구 오류 수정: 이 기능의 초기 생성본은 `sheetPr`의 `outlinePr` 순서가 잘못되어 Excel에서 sheet4.xml 로드 오류가 발생했습니다. 아래 월별·수식 검증은 XML 스키마 순서를 검사하지 못했습니다. 현재 운영본은 값·수식·조회 기능을 유지한 채 순서만 고쳤으며 [XML 복구 오류 검증](2026-10-18_XML복구오류_검증.md)과 `excel_xml_repair_validation.json`이 최신 구조 검사·해시입니다.

작업일 2026-10-18, 실제 거래 기준일 2026-10-15. 사용자 요청은 (1) 첫 번째 표의 이체 금액이 선택월만 집계하는지 확인, (2) 하단 WRAP 원장도 선택월만 기본 조회하도록 수정하는 것입니다. 변경 전 `4aca6c9` 파일·문서는 [history/2026-10-18/01](history/2026-10-18/01/README.md)에 보관합니다.

## 1. 첫 번째 표는 이미 선택월 기준

`잔액!E7:E15`는 보내는 계정, `F7:F15`는 받는 계정을 구분해 `H64:H500=$B$3`인 원장만 집계합니다. H열은 거래일의 월 첫날이며 B3도 실제 월 첫날 날짜이므로, B3가 2026-10-01이면 10월 이체만 잡힙니다. 전월말(B열)은 이전 기간 누적 잔액이고 조회월 잔액(G열)은 그 이월액에 해당 월 입출금·이체를 반영한 금액입니다.

이체에는 **WRAP 내부 계정 이동**도 포함합니다. 10월의 원장 기준:

| 구분 | 이체 보냄 | 이체 받음 |
|---|---:|---:|
| 생활비 | 2,537,839 | 687,510 |
| 임시보관 | 61,000 | 61,000 |
| 합계 | 2,598,839 | 748,510 |

합계에는 임시보관 → 생활비 61,000원이 양쪽에 포함됩니다. 따라서 은행 간 실송금 총액(나감 2,537,839 / 들어옴 687,510)과 다르며, 내부 이동은 WRAP 합계에서 상쇄됩니다. 첫 번째 표의 열 구성·집계 수식·금액은 변경하지 않고 안내만 보완합니다.

## 2. 선택월에 맞춘 기본 화면

기존에는 B35가 최신 원장월을 따르는 별도 선택이었고, 전체 원장은 과거 64~230행이 펼쳐진 반면 10월 231행 이후는 숨겨져 있었습니다. 이 때문에 상단 조회월을 바꿔도 아래가 같은 달로 바뀌지 않았습니다.

- **조회월 B3**: 상단 잔액·기존 상세 내역·새 하단 원장에 공통 적용됩니다.
- **B35**: `MONTH(B3)` 자동 표시입니다. 별도 월 드롭다운은 제거하고 입력 칸 색상도 없앴습니다.
- **기존 내역·이체 조회표(38~59행)**: 동일 조회월로 연결하고 실제 표시 페이지를 범위 안으로 보정합니다. 잘못된 E35 페이지 입력 상한 참조도 현재 페이지 수 F35로 바로잡았습니다.
- **선택월 WRAP 원장(501~525행)**: 같은 탭 하단에 22건씩 최신 기록순으로 표시합니다. 페이지는 B501에서 고릅니다. 월을 바꿔 현재 페이지가 범위를 벗어나면 마지막 유효 페이지로 보정하며, 0건인 월은 빈 표·1/1페이지로 표시합니다.
- **전체 입력 원장(A64:Y500)**: 원래 주소·내용·수식·행번호를 유지하고 기본 접어 둡니다. 편집이나 새 거래 입력이 필요할 때만 왼쪽 **+**를 펼칩니다. 이 영역의 184건을 삭제하거나 월별로 재정렬하지 않습니다.
- 새 조회표는 조회용입니다. 노란 페이지 칸 외에 직접 거래를 입력하지 않습니다. ‘원장 N행’ 링크가 원본 위치를 안내하며, 숨겨진 원본을 보려면 먼저 +를 펼칩니다. 입력 오류가 있으면 원장 안내 링크에도 건수를 표시합니다.

긴 메모는 조회표에서 40자 요약과 생략 표시로 보여줍니다. 전문은 원본 행에 그대로 있으며, 금액·내용·원본 메모를 잘라 저장하는 것은 아닙니다.

선택월 필터는 `거래일 >= B3`, `거래일 < EDATE(B3,1)`입니다. 월말 시각도 포함하며, 과거의 P/Q 분류가 빈 `이동(기존)` 행도 실제 잔액에 반영되는 원장이므로 제외하지 않습니다. 날짜는 내림차순, 같은 시각은 원본 행 순서로 정렬합니다. 원본에서 날짜가 월 단위로만 기록된 것은 월만 표시하며 실제 일자를 만들지 않습니다.

매크로나 정적 AutoFilter에 의존하지 않고 수식으로 연동합니다. 원본을 정적으로 숨기는 것만으로 월 변경을 구현했다고 간주하지 않습니다. 원본은 보존·입력용으로 접고, 실제 기본 조회는 B3 연동 수식 표가 담당합니다. 인쇄 범위도 새 조회표까지 확장합니다. 기본 접힌 입력 원장은 인쇄에서 제외됩니다.

## 보존·검증

스크립트는 `scripts/balance_selected_ledger.py`, 결과·현재 해시는 [balance_selected_month_validation.json](balance_selected_month_validation.json)입니다. 3~12월의 상단 계정별 집계와 새 원장 표시를 원장 독립 집계와 대조하고, 7·8월 두 번째 페이지, 큰 페이지 번호 후 월 변경, 월말 23:59:59를 시험합니다.

원본 A64:Y500의 값·수식, RAW 전체, 월간·계산기·생신 사용 239,000원·정산대기 0원·WRAP 6,685,466원·생활비 4,535,466원을 보존합니다. 표시 시트 수·순서는 그대로이며, 새 시트나 실제 은행 거래는 추가하지 않습니다. 원래 스타일 정의·VBA·버튼·그림·관계 파일의 바이트도 대조합니다.

매크로 없는 임시 XLSX에서 LibreOffice로 재계산한 뒤 원본 XLSM에 수식 캐시만 옮깁니다. Excel 데스크톱에서 매크로 실행·드롭다운 클릭·그룹 펼침을 직접 실행한 검증은 포함하지 않습니다. 이전 기능의 시나리오 검증은 당시 파일의 이력이며 이번 검증과 구분합니다.

검증 결과: **3~12월 조회 10개 및 추가 시나리오 4개 통과**, 수식 오류 0건입니다. 10월 하단 원장 15건은 모두 선택월이며 11·12월은 0건입니다. 월별 원장 건수는 3월부터 순서대로 11, 22, 27, 21, 30, 40, 18, 15, 0, 0건입니다. 원장 전체 184건과 기존 재무 값은 보존했습니다.

최종 표시 보완은 새 조회표의 메모 요약·금액 서식 셀만 바뀌었음을 XML 대조로 증명한 뒤 기본 10월을 다시 재계산했습니다. 재무·월 필터·페이지 수식과 다른 패키지 파트는 전체 월/시나리오 시험 후보본과 바이트가 같으며, 해당 범위를 결과 JSON의 `targeted_display_recheck`에 남깁니다.
