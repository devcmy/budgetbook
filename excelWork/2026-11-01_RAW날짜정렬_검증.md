# RAW 날짜 정렬과 거래 연결 유지

기준 커밋 `930e37e`. 변경 전 파일·문서는 [history/2026-11-01/03](history/2026-11-01/03/SNAPSHOT.md)에 보관합니다. 데이터는 10/31까지 기존 2,588건 그대로이며, 이번 변경은 정렬 지원입니다.

## 사용법

- RAW **A열 ‘일시’의 ▼ → 날짜 오름차순(오래된 항목순) / 내림차순(최신 항목순)**을 선택합니다. 날짜는 월·일만 표시하지만 실제 연도·시간·소수초를 포함해 정렬됩니다.
- B열 ▼의 월 필터도 계속 사용할 수 있습니다. 표의 기본 필터/정렬을 사용하고 A열 값만 따로 복사해 순서를 바꾸지 않습니다.
- **AP열 ‘거래ID’는 수정하지 않습니다.** O~AO 계산 열은 숨겨두었으므로 화면에서는 N 입력확인 다음에 거래ID가 보입니다. 거래ID가 거래와 함께 이동하므로 정렬 후에도 예비비·잔액·추가 실지출·메모가 같은 거래를 가리킵니다.
- 예비비 사용등록 F열, 잔액 원장 W/X열에는 이제 현재 행번호가 아닌 **RAW AP열의 거래ID**를 씁니다. 기존 연결 숫자는 그대로 보존했습니다. 과거 설명·메모의 ‘RAW n행’은 변경 당시의 원래 행번호로, 이번에 부여한 거래ID n과 같습니다. 정렬 후의 화면 행번호로 찾지 않습니다.
- 새 입력은 필터를 모두 해제한 뒤 빈 행에 A 일시 / C~I 거래를 입력합니다. 준비된 빈 행의 거래ID와 계산식은 그대로 둡니다. 정렬 후에는 다음 입력 위치가 달라질 수 있으므로 오른쪽 ‘다음 입력 위치’ 링크를 사용할 수 있습니다.

## 원인과 수정

기존 RAW 시트는 행번호 기반 연결을 보호하기 위해 정렬을 금지했습니다. 단순히 정렬 허용 설정만 바꾸면 잠긴 계산 열 때문에 Excel이 계속 거부할 수 있고, 보호만 해제하면 기존 거래 연결이 다른 행을 가리킬 수 있었습니다.

1. 표 범위를 `A1:AO4001`에서 **A1:AP4001**로 확장하고 4,000개 입력 행에 고유 거래ID 2~4001을 넣었습니다. 실제 거래·사용자 메모·수기 분류/부담/결제 보정은 그대로입니다.
2. RAW의 자기 행 참조는 표의 `#This Row` 참조로 바꾸었습니다. 예전 `ROW()`로 판단하던 역사적 거래 예외도 거래ID 기준으로 바꿔 정렬 위치에 영향을 받지 않게 했습니다.
3. 예비비·잔액·월별 추가 지출·계산기의 고정 행 연결을 거래ID `MATCH` 조회로 바꾸었습니다. 중복 판정과 월별 메모 순번도 표시 행순서가 아닌 고정 ID를 기준으로 합니다. 메모는 여전히 I열 표시용이며 금액·분류·중복 판정에는 쓰지 않습니다.
4. RAW 시트 보호를 해제하여 표 전체를 기본 정렬할 수 있게 했습니다. 계산 열은 계속 숨겨두고 거래ID에는 중복/범위 검사와 변경 금지 안내를 붙였습니다. **데이터 유효성 검사는 붙여넣기로 우회될 수 있으므로 잠금 보안이 아닙니다.** 거래ID·숨김 수식 수정, 전체 행삭제, 기존 거래를 다른 거래로 덮어쓰기는 하지 않습니다. 다른 시트의 보호 설정은 바꾸지 않았습니다.

## 확인 범위

상세 결과와 최종 파일 해시는 [raw_sort_20261101_validation.json](raw_sort_20261101_validation.json), 현재 상태 요약은 `audit.json`에 기록합니다.

- 임시 매크로 없는 사본을 다시 계산하여 변경 전/후 및 날짜 오름차순·내림차순·ID순 원상복원 상태를 대조합니다. 표의 A:AP 전체 레코드를 이동시키며 오른쪽 안내는 이동하지 않습니다.
- 모든 월·계산기 및 숨김 계산의 수치/날짜, ID별 원본·분류·중복·달력 보조값을 비교합니다. 예비비 사용/정산과 WRAP 잔액은 기존 수식을 재사용하지 않는 독립 모형으로 확인합니다.
- 정렬 후 임시 거래 입력·짧은/긴 거래키 중복·원본보다 중복본이 먼저 나타나는 순서·메모 수정 및 삭제를 시험합니다. 시험 데이터는 운영 파일에 넣지 않습니다.
- 기존 VBA·컨트롤·그림·스타일은 바이트 동일하게 보존합니다. ZIP 무결성·XML 파싱·시트 요소 순서·병합/열 범위·표/유효성 개수를 검사하며 검증 시트를 추가하지 않습니다.
- Microsoft Excel 실제 UI에서 메뉴 클릭/복구 대화상자를 실행한 검사는 아닙니다. 표 보호 해제와 전체 레코드 재배열 후 재계산을 검증한 범위입니다. 임시 평가기의 원본 줄바꿈 정규화 한계는 기존과 같고, 사용자 RAW 메모 원문은 수정하지 않습니다.
