# iPhone 17 Pro Max 디자인 02

2026-10-06 사용자 요청 반영. 사용자 개인용, iPhone 17 Pro Max, iOS 27의 Glass 방향을 기준으로 합니다. 앱의 원래 계산 기준은 엑셀이며 편한가계부는 입력·관리 참고입니다.

## 사용자 확정과 비예비비

사용자는 비예비비를 **카드가 아닌 계좌에서 지출하되, 미리 정해진 예비비 계획에 따른 사용이 아닌 현금성 지출**이라고 정정했습니다. 이를 ‘예비비 외 모든 지출’로 일반화하지 않습니다. 기존 엑셀의 추가 실지출 표와 WRAP 원장이 근거이며 추가 파일이 필요하지 않았습니다.

| 이번달 메뉴 | 2026-10-05 표시 | 근거 |
|---|---|---|
| 비고정비 | 286,580원 | 10월!H38 및 일별 달력 실지출 |
| 고정비 | 1,248,055원 | 10월!H37; 예상·미확인 유지 |
| 비예비비 | 11,900원 | 10월!D52; 두끼떡볶이 RAW 2333행 / WRAP 원장 231행 |
| 예비비 사용 | 0원 | 10월!N69 목적자금 실제 사용 합계 |

이 네 메뉴는 모두 더할 수 있는 독립 지출 분류가 아닙니다. 비예비비 11,900원은 변동지출에 이미 포함되어 있고 10월!G52=11,900, H52=0입니다. 상세에서 발생액/기집계/추가 금액을 함께 표시합니다. 공동통장 납입 50,000원은 현금 소비로 합치지 않습니다.

현재 지출·적립 합계는 1,248,055 + 286,580 + 공동계좌 적립 50,000 − 환급 300 = 1,584,335원입니다. 총수입 2,780,230원에는 예상 월급이 섞여 있으므로 남는 돈 1,195,895원은 **예상**으로 표시합니다. 예비비 사용도 기존 달력/고정/추가 항목과 거래를 연결한 뒤 한 번만 반영해야 합니다. 아빠 생일은 9월 사용 완료를 10월로 이동하지 않습니다.

## 화면과 밀도

기준 화면은 440×956pt, 3배 스케일에서 1320×2868 픽셀입니다. Apple의 공식 기기 사양과 대응하는 디자인 기준이며 실제 안전영역은 iOS가 결정합니다. 큰 소개 영역을 없애고, 작은 결산 카드 → 네 지출 카드 → 일별 금액 달력 → 선택일 기록 → 테트리스/자금 잔액 순으로 배치합니다. 기본은 촘촘한 보기이며 설정에서 여유 있는 간격으로 전환합니다. 실제 버튼은 44pt를 기준으로 구성하고 주요 금액은 큰 숫자와 원 단위로 유지합니다.

일별 달력은 원본 10월 1~5일의 17,300 / 30,500 / 5,000 / 112,890 / 120,890원을 표시합니다. 이후 날짜는 ‘—’/미입력이며 0원으로 채우지 않습니다. 상세 기록 ID는 RAW 재분류를 기준으로 연결하되 전체 계산을 재수행한 결과로 주장하지 않습니다. 금액이 월간표에서 유래한 스냅샷이라는 경계를 유지합니다.

## Glass 적용

Apple HIG Materials 및 Tab bars는 Glass를 탐색·조작 층으로 구분합니다. 이에 따라 하단 탭, 월 선택, 입력 버튼에만 유리 효과를 사용하고 거래·금액 카드에는 읽기 쉬운 일반 배경을 유지합니다. 네이티브는 시스템 TabView와 iOS 26부터 제공되는 glassEffect를 사용합니다. iOS 27은 시스템의 최신 Glass 표현과 사용자 선호를 따릅니다. iOS 27 안내에서 Glass의 선명도 조절이 소개되어 있음을 확인했으며 앱에서 임의로 이를 복제하지 않습니다.

웹 시안은 CSS backdrop-filter로 표현하므로 실제 광학 굴절/유동적인 모양 변화와 동일하지 않습니다. iOS 접근성 투명도 감소 및 앱 설정의 감소 옵션을 지원하고, 웹의 reduced-transparency / reduced-motion 선호도도 반영합니다. Glass의 실기기 성능과 실제 OS별 동작은 아직 확인하지 않았습니다.

## 설정 탭과 표시 이름

5개 탭과 25개 메뉴/표시 항목을 변경합니다. labels.json을 브라우저/SwiftUI에 동일하게 제공하며 안정적인 id와 기본 이름, 그룹, 길이를 보관합니다. 탭은 12자, 메뉴는 20자 이내로 제한하고 빈 이름·제어 문자를 거부합니다. 너무 긴 탭 표시는 줄임 처리하되 이름 편집 화면에서 전체를 확인합니다. 원본 거래의 계좌·분류·내용을 재명명하는 기능이 아닙니다.

변경 이름은 화면의 탭·제목·메뉴에 즉시 반영됩니다. 개별 이름과 전체 이름을 복원할 수 있으며 이름 복원은 거래나 화면 설정을 지우지 않습니다. iOS UserDefaults와 브라우저 localStorage에 이름·밀도·투명도 설정만 저장합니다. JSON 저장값의 유효성을 검사해 알 수 없는 id나 손상된 이름은 기본값으로 되돌립니다. 거래 시안은 영구 저장하지 않습니다.

## 구현/검증 경계

SwiftUI 프로젝트 리소스에 snapshot.json, labels.json과 새 화면 소스를 연결했습니다. Xcode 26 이상 SDK가 필요하고 iOS 27 확인에는 해당 OS를 지원하는 최신 Xcode를 사용합니다. 이 Linux 환경에서 iOS 빌드는 실행하지 않았습니다.

브라우저 UI는 이름 변경·초기값 복원·설정 API 호출/저장값 재로드·비예비비의 중복 제외·날짜 조회·입력 회귀를 검증합니다. 저장소 테스트는 명시적인 메모리 대역이므로 실제 디스크 지속성 검증이 아닙니다. 거래 계산 모듈 및 인계의 20개 승인 사례는 아직 구현/검증하지 않았습니다.
